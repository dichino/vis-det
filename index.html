About Vis Det

Vis Det – Social Impact Tool

Vis Det is a practical tool for social entrepreneurs, nonprofits and local initiatives who want to understand, measure and show the effect their work has on society.

Why this exists

The prototype is inspired by Norge Unlimited's work with local social entrepreneurship, neighbourhood incubators and impact documentation. It explores how early impact data can be captured before it becomes formal reporting.

Journal evidence

Document evidence

Log entries with people reached, tags, and optional files so progress can be reviewed later.

People reached

Track reach

Keep simple counts close to the qualitative notes that explain what changed.

Surveys and QR

Collect responses

Create lightweight surveys, export them as standalone HTML, and import response JSON files.

Local-first data

Stay local

Data is stored in this browser with IndexedDB. Export and import are explicit file actions.

How it works

1 Document activities

Write short notes from workshops, meetings and follow-ups.

2 Add evidence and reach

Record people reached, tags and optional attachments.

3 Collect feedback

Use lightweight surveys and import responses locally.

4 Summarize impact

Shape local evidence into an impact story and export a clear draft.

05

Engineering decisions

Problem / trade-off

Testable without account infrastructure

The prototype uses IndexedDB through Dexie so project data persists locally while staying simple enough for static deployment.

Decision

Validate before import

JSON and CSV imports are normalized, previewed and checked for relation errors or duplicates before valid records are merged.

Why

Derived impact story, not static copy

Evidence Readiness, timelines, summaries, markdown exports and writing prompts are generated from current stored records.

Why

Two-language interface

A structured translation object updates UI text, placeholders, titles, summaries and the live entry preview in English or Norwegian.

06

Implementation evidence

Dexie schema

The app persists projects, journal entries, attachments, surveys and imported survey responses in browser storage.

db.version(2).stores({
  projects: '++id, name, description, createdAt, updatedAt',
  entries: '++id, projectId, text, count, tags, createdAt',
  attachments: '++id, entryId, name, type, size, data',
  surveys: '++id, projectId, title, description, createdAt',
  responses: '++id, surveyId, submittedAt'
});

Evidence readiness logic

The score combines actual project records: journal coverage, timeline spread, reach, tags, attachments, surveys, responses and recency.

const components = [
  { key: 'journal', points: Math.min(entries.length / 12, 1) * 18 },
  { key: 'spread', points: Math.min(uniqueMonths.size / 6, 1) * 14 },
  { key: 'surveys', points: Math.min(surveys.length / 2, 1) * 10 },
  { key: 'responses', points: Math.min(responseCount / 10, 1) * 12 }
];

Impact package export

07

Prototype boundary

Built for this prototype

  • Local-only data
  • Not a production CRM or reporting system
  • Portable import/export files
  • Static deployment architecture

Production evolution

  • Shared server-side persistence
  • Authentication and role-based access
  • Multi-user synchronization and backups
  • Auditability for formal reporting
08

Technology

A deliberately lightweight browser-native architecture: HTML for structure, CSS for the responsive design system, JavaScript for state and product logic, IndexedDB/Dexie for local persistence, and static deployment for sharing the prototype.
